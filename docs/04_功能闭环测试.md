## 一、测试体系（五层）

```
L1 构建验证    cmake 构建 + 产物检查（nuttx.bin / nuttx-app.bin / 段布局）
L2 烧录验证    tools/usb_stable.sh：两镜像（0x2000 + 0x20000）+ hash 校验断言
L3 启动验证    MCUboot banner → NuttShell (NSH)；console 在 /dev/ttyUSB0
L4 功能闭环    外设/服务 → 命令与工具 → 结果验证
L5 复现验证    干净构建目录 + deploy.sh 幂等性 + manifest 完整性
```

**回环定义**：文件树 → deploy → 构建 → 烧录 → 运行 → 验证 → 记录

## 二、测试工具（本轮新增/重写）

| 工具 | 用途 |
|---|---|
| `tools/usb_stable.sh` | MCUboot **两镜像**烧录，校验两个镜像均完成 hash；失败即非零退出 |

## 四、已定位但未打通的测试（🔶，根因明确）

| 项 | 现象 | 根因/下一步 |
|---|---|---|
| 面板显示 | `EK79007 DCS 0xb2 failed: -110`（超时）→ `/dev/fb0` 未注册 | I2C0 本身可用（摄像头在 0x30 应答），GT911 与面板同时无应答 → **LCD 模组连接/供电**（FPC 方向或 J1→J6 跳线），非驱动逻辑 |
| 触摸 | `GT911 not detected at 0x5d or 0x14` | 同上（GT911 在 LCD 模组 FPC 上） |
| 摄像头出帧 | `VIDIOC_S_FMT` EINVAL → 已修白名单后仍不通 | RAW10 与 NuttX V4L2 上层语义不匹配；正解是接通 ISP 输出 RGB565/YUV422 |
| ai_agent CLI 输入 | `vela>` 提示符已可见（TX 修复生效），但输入无响应 | NSH 与 agent CLI 均收不到字符 → 排除 fd/线程（已实测 stdin/stdout 均为 `/dev/console`） |
| LLM 真实对话 | MiMo key 返回 HTTP 401 Invalid API Key | 需有效 key/额度 |

cd <openvela 根>

# L2 烧录（两镜像）
contest2026_342_ezdezhandui/tools/usb_stable.sh

# L3/L4 启动与功能
