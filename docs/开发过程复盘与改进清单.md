## 二、开发时间线（8/6–8/20）

### 阶段 0：环境搭建（8/6，踩坑笔记 #01）——goldfish 模拟器跑通
repo 2.17 太老 → 换新版；gerrit 自举被墙 → ghfast 代理；tuna 挂死 → gitee 源；python2 抢 CMake → PATH 前置；缓存残留 → rm cmake_out；模拟器缺镜像 → 软链产物；无显示器 → -nographic。

### 阶段 1：方案定稿 + ai_agent 验证（8/12，踩坑笔记 #01）——goldfish + ai_agent 跑通
- ✅ `ask 现在几点了` 内置工具应答（无 LLM key 也通，ReAct 链路工作）
- 交互通道血泪史：**stdin 管道 + -qemu -nographic 是唯一可靠通道**（expect/pty/adb/telnet 全不通）
- 教训：`pkill -f` 三次误杀自己（用 `[q]emu` 字符类）；多模拟器 AVD 互斥；cwd 漂移

### 阶段 2：esp32p4 移植（8/12–18，踩坑笔记 #02）——核心工作量
- 改动 284 文件（201A/74M/8D），详见 `board/esp32p4_vela/README.md` 代码地图
- 关键坑：HAL 版本锁定 ≥8d0a898；debug.h 位置差异（68 处替换）；NUTTX_BINARY_DIR 未定义；LD_SCRIPT 多文件；riscv_mtimer 条件编译；**HAL patch 必须固化**（cmake_out 重 clone 丢手工修改，丢过一次）；无 libatomic → 自写 esp32p4_atomic.c；tools/espressif 缺 6 文件；board_app_initialize 缺失 → 新写 appinit
- **8/20 补漏**：`arch/risc-v/Kconfig` 注册块（36 行）第一次提交时漏了——移植 commit 前用 `git status` 对照笔记文件清单逐项核对

### 阶段 3：板卡到货 + 真机识别（8/18）
- 实际为 **ESP32-P4X-C5-Function-EV-Board**（C5-MINI-1 模组）；芯片 rev3.2、flash GD25Q128E 16MB
- console 切 USB Serial/JTAG（ttyACM0）；udev 规则 + dialout 组解决权限

### 阶段 4：烧录攻坚（8/18–19）——当前瓶颈
- **P4 ROM 需要 ram-only-header 格式镜像**（mkimage 旧版不支持，手动 esptool elf2image 生成）
- esptool stub 崩溃（rev3.2 不兼容，5.3.1/4.10 都崩）；ROM 模式 USB 擦写断流；UART0 下载模式无响应
- **重大线索**：ram-only 镜像曾被 ROM 接受并加载，app 早期 crash（load access fault @0x25）——加载链路已通
- 推荐路径：JTAG 烧录（openocd-esp32 已备）；**0x25 crash 反汇编分析应优先于 JTAG**

### 阶段 5：工作区重做 + 提交（8/20）
- **官方 manifest 重做**：`repo init -u <gitee 专属仓> -m contest2026_342_ezdezhandui.xml`（gitee 有镜像且与 GitHub 同步；GitHub 源会挂死）→ `repo sync -c -j8`（两次 TLS 中断重试后成功，旧树保留到新树验证）
- 移植重放发现 Kconfig 遗漏 → 补 → 新树编译通过 + mkimage 自动 ram-only
- 作品仓整理（README/文档/skills/清理模板骨架/manifest linkfile 同步）→ fork + PR #1（CLA 已签，合入权限待组委会）
- **网络攻坚**：github.com:443 直连间歇不通，api.github.com 稳定 → Git Database API push 脚本（/tmp/git-api-push.py）

## 四、待优化清单（按优先级）

### 🔴 立即（T1 收尾，已过期）
1. **分析 0x25 crash 现场**（不依赖板子）：`riscv-none-elf-objdump -d cmake_out/.../nuttx` 定位 PC=0x25 附近指令与调用链——若崩溃点很浅（UART/时钟初始化），一次修改就可能点亮串口，比 JTAG 快
2. **JTAG 烧录验证**：动手前先确认 openocd-esp32 对 esp32p4 flash 写入的支持（cfg workarea/stub 配置），避免再次"试了发现不支持"；烧完必须停 OpenOCD 才能看 ttyACM0
3. **git 对齐**：远端 4f959cc9 vs 本地 sha 不同（GitHub 时区规范化，内容等价）——合入后 git fetch 对齐，避免分叉

### 🟡 短期（T1→T2 过渡）
4. **goldfish 回归**：riscv_mtimer 条件编译是全局改动，影响所有 RISC-V 板——重建 goldfish + ai_agent 确认没弄坏（也是演示兜底资产）
5. **HAL patch 可复现性验证**：`rm -rf cmake_out` 全量重构建一次，确认 HAL 重 clone 后 patch 自动 apply（当前从未验证过全流程）
6. **明确 T1 决策点**：8/22 前串口点不亮 → 启动 R1 兜底（goldfish 全功能演示 + 移植材料）
