> 本轮背景：板子的 **CP2102 UART 桥（/dev/ttyUSB0）从主机 USB 上消失了**
> （`lsusb` 只有 Espressif USJ `303a:1001`，无 `10c4:ea60`；cp210x 驱动已加载但无设备），
> 而 NuttX console 配在 UART0 → 临时把 console 切到 **USB-Serial/JTAG** 做诊断：
> ```
> CONFIG_ESPRESSIF_USBSERIAL=y
> # CONFIG_UART0_SERIAL_CONSOLE is not set
> CONFIG_OTHER_SERIAL_CONSOLE=y
> ```
> 诊断完已把 defconfig 与板载固件**恢复为交付配置（UART0 console）**，并复验启动链路正常。

### 8.2 本轮新取得的确定性结论

1. **I2C0 是好的**：SC2336 摄像头 SCCB **与 GT911 共用 I2C0**（`ESP32P4_CAMERA_I2C_PORT = ESPRESSIF_I2C0`），
   摄像头 `Chip ID 0xcb3a` 正常应答 → I2C0 控制器与 GPIO7/8 通路无问题。
   因此面板（DSI DCS 超时）与 GT911（I2C 无应答）同时失效，指向 **LCD 模组本体/供电/FPC/跳线**，
   而不是 SoC 外设。
2. **`/dev/input0` 存在 ≠ 触摸可用**：`esp32p4_touch_gt911.c` 在两次探测都失败后仍会
   `gt9xx_register("/dev/input0", …)`（注释写明"为诊断保留节点，open() 时再探"）。
3. **视频栈的错误打印默认被编译掉**：`verr()` 需要 `CONFIG_DEBUG_VIDEO_ERROR=y`，
   所以 `VIDIOC_S_FMT` 的 EINVAL 现场只有返回值、没有原因。定位该问题必须打开该开关。
4. **构建健壮性缺陷（本轮修掉 2 处，见 8.3）**：干净树连续构建会因 HAL 兼容补丁
   重复/顺序问题直接 `config fail`。

### 8.3 本轮修掉的构建缺陷（已进作品仓）

| 缺陷 | 现象 | 修复 |
|---|---|---|
| HAL 补丁不幂等 | 第二次 configure 报 `git apply 失败：sdkconfig.h:683/941` → `Configuring incomplete` | 打补丁前 `git reset --hard <钉定 HAL 版本>`；新增 `vela_apply_hal_patch()`：`--check` 通过才 apply、反向 check 通过视为已应用、两者都不通过才 FATAL |
| 两个补丁互相踩上下文 | 0001 的 hunk 落在 0002 的锚点上下文里 | 固定顺序 **0002 → 0001**；并删除 0001 中两段过时 hunk（submodule 指针噪声、HAL 已自带的 MEMPROT 注释） |

验证：`rm -rf cmake_out` 后单条 `./build.sh … --cmake -j8` → **9:11 构建成功**，
两个补丁均打印 `HAL patch applied`，kconfig 无错误，产出双镜像。

### 8.4 本轮踩到的两个新坑（记录，避免再花时间）

1. **`CONFIG_DEBUG_FEATURES=y` 会让 CMake 的 kconfig 解析报致命错**
   （`nuttx_kconfig.cmake:48/76: string REGEX MATCH needs at least 5 arguments`），
   进而 `Configuring incomplete` → `build.sh: config fail`；
   把 DEBUG_* 行从 defconfig 撤掉后同样的树立刻构建成功。
   → 想开 `CONFIG_DEBUG_VIDEO_ERROR` 需要先单独修这个解析问题。
2. **删 `.config` / `CMakeCache.txt` 都不能触发重新配置**：
   `lunch` 只在 `CMAKE_BINARY_DIR` 不存在时才跑 cmake，所以改 defconfig 后
   必须 `rm -rf cmake_out` 才能生效（否则 ninja 会以 `loading 'build.ninja': No such file` 失败）。
