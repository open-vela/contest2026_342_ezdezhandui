# 踩坑笔记 #06：GT911 触摸屏驱动

> 时间范围：2026-09-15 ~ 09-16。目标：GT911（I2C 0x5d）在 1024×600 面板上跑通，
> 并接入 LVGL 作为输入设备。
>
> **结论：已真机闭环** —— 光标与手指对位正确（用户实测确认）。
> 本文记录 4 个坑，其中**坑 2 是"触摸完全没反应"的真根因**。

硬件：GT911 挂在 **I2C0**（与摄像头 SCCB **共用总线**），
本板**没有把 INT 脚接出来**，所以驱动跑**轮询模式**：

```
GT911: no INT line routed; running in polling mode
GT911 touchscreen registered at /dev/input0 (0x5d)
```

---

## 坑 1：产品 ID 校验写错 → 控制器一直被误判为"未检测到"

上电探测阶段读 `0x8140` 起的 4 字节产品 ID，实测：

```
GT911: raw ID at 0x5d = 39 31 31 00      ← ASCII "911\0"
GT911: product ID "911" at 0x5d
```

校验逻辑原来与实际读回的字节序列不匹配，导致**明明在总线上、却一直走"未检测到"分支**。
修正校验后识别正常。

> 教训：**先把原始字节打出来**再写校验，别凭"应该是什么字符串"去写比较。

---

## 坑 2：`gt9xx_i2c_write()` 用两条消息 + `I2C_M_NOSTART` → 每次 `read()` 都 `-ETIMEDOUT`

**这是"触摸完全没反应"的真根因。**

原实现把一次寄存器写拆成**两条 I2C 消息**：
第一条发寄存器地址，第二条带 `I2C_M_NOSTART` 发数据值。

问题在于 **`i2c_transfer()` 会给每条未带 `I2C_M_NOSTOP` 的消息发 STOP**，总线已经释放；
而 `esp_i2c.c` 对 `I2C_M_NOSTART` 的处理是**跳过地址阶段、直接发数据** ——
于是在一条**已经结束的事务**上凭空推数据 → `esp_i2c_sem_waitdone` 超时。

后果：**每次 `read(/dev/input0)` 都在 `gt9xx_set_status(dev, 0)` 处返回 `-ETIMEDOUT`**。

这解释了当时那个很迷惑的现象：**初始化看起来完全健康**
（板级 probe 读 `0x8140`、状态读 `0x814e` 都是"写地址+读"的正常形态，所以能成功），
**只有"写"会失败**。

**修复**：改成**一条消息**承载 `[reg_hi, reg_lo, val]`。

**实测证据**：修复后 `tc` 能打印真实坐标 `npoints=1 flags=19 x=875 y=406`，
LVGL 日志 `touchscreen /dev/input0 open success, maxpoint 1`。

---

## 坑 3：模组倒装 180° → 坐标反向

修好 I2C 之后出现"摸左上角、光标跑到右下角"。先排除了缩放问题：
读 GT911 配置块得到 **`x_max=1024 y_max=600`，与面板完全一致**，所以不是量程问题。

**结论：GT911 模组在板子上是倒装 180° 的** → 需要**双轴镜像**。

**修复**：在 `struct gt9xx_board_s` 里加板级接口，由板级配置声明镜像尺寸：

```c
/* include/nuttx/input/gt9xx.h */
uint16_t xmirror;
uint16_t ymirror;
```

```c
/* 驱动内 */
if (dev->board->xmirror > 0 && dev->board->ymirror > 0)
  {
    x = dev->board->xmirror - 1 - x;
    y = dev->board->ymirror - 1 - y;
  }
```

```c
/* esp32p4_touch_gt911.c */
.xmirror = 1024,
.ymirror = 600,
```

> 设计取舍：镜像放在**板级 board 结构**里而不是驱动里写死，
> 因为"模组装没装反"是**板子属性**，换板子/换模组不该改驱动。

---

## 坑 4：I2C0 与摄像头 SCCB 共用 → 谁先初始化谁负责建总线

GT911（0x5d）与 SC2336 SCCB（0x30）**在同一条 I2C0 上**。
`esp_i2cbus_initialize()` 是**引用计数**的，所以两个驱动都可以各自调用，
但必须保证**先来的那个**把总线建起来。实测总线扫描：

```
I2C0 @400000 Hz: ACK from 0x18   ← ES8311 音频 codec
I2C0 @400000 Hz: ACK from 0x30   ← SC2336 摄像头 SCCB
I2C0 @400000 Hz: ACK from 0x5d   ← GT911 触摸
I2C0 @400000 Hz: scan done, 3 device(s)
```

---

## 附：LVGL 侧的两个联动项

1. **输入设备的 `continue_reading` 语义**：NuttX 的 gt9xx **每次 read 都返回完整样本**
   （`npoints=0` 也算成功），所以移植层**不能**"read 成功就继续读"，
   否则 LVGL 会死循环在输入回调里（详见 `踩坑笔记_05` 坑 4）。
2. **打开指针光标**便于对位调试：`LV_NUTTX_TOUCHSCREEN_CURSOR_SIZE=24`。
   调坐标时一目了然，调完可以关掉。
