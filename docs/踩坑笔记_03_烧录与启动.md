# 踩坑笔记 #03：ESP32-P4X 烧录与启动（0x25 根因 → NuttX 完整启动）

> 2026-08-18/21。目标：板卡（ESP32-P4X-C5-Function-EV-Board，rev3.2）烧录并启动 NuttX。
> **结论：NuttX 内核完整启动**（调度器 idle 运行）——4 个根因级修复（链接布局 / 烧录偏移 / XIP 污染 / CLIC 中断风暴）；**USB-Serial console 数据未达主机**（T2 第一项）。

## 里程碑链路（按修复顺序）

| 阶段 | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1. 链接布局 | 早期 crash `load access fault @0x25` | HAL sdkconfig.h 的 `CONFIG_APP_BUILD_USE_FLASH_SECTIONS=1` 劫持链接 → 代码链到 0x40000000（**flash XIP 映射区，非 RAM**）→ ram-only 加载后执行空 flash | `esp32p4_flat_memory.ld`：条件改 `CONFIG_ESPRESSIF_SIMPLE_BOOT` + rev3 的 `sram_seg`（上游 else 分支引用 sram_low 是 rev<3 专属——**rev3+SIMPLE_BOOT 组合上游从未跑通**） |
| 2. 烧录偏移 | ROM 报 `invalid header`（读到的不是烧的内容） | **P4 的 bootloader 偏移 = 0x2000**（`BL_OFFSET`，espressif_esptool_common.cmake 中 `CONFIG_ARCH_CHIP_ESP32P4` 专属）——烧 0x0 无效 | esptool **≥4.12.0**（2026-07-13 才支持 rev3.2/ECO7，5.3.1/4.10 stub 全崩）`write_flash 0x2000 nuttx.bin`；或官方 `cmake --build <dir> -t flash`（⚠️ 其 `write-flash` 参数名与 4.12 的 `write_flash` 不兼容） |
| 3. XIP 污染 | bss 垃圾、CPU 跳飞（0x8C5B/0x8FF8 等垃圾地址） | `esp_start.c` SIMPLE_BOOT 分支调 `map_rom_segments`，用 `_image_irom_lma`（修复后 = **SRAM 地址**）当 flash 物理地址配置 MMU → 整片 SRAM 被无效映射污染 | SIMPLE_BOOT 跳过 `map_rom_segments`（只 MCUBOOT 需要 XIP） |
| 4. CLIC 风暴 | 早期中断风暴（irq_unexpected_isr → 反复） | ROM 遗留 CLIC 中断源在 NuttX IRQ 表就绪前触发；`up_disable_irq` 无 IRQ_UNMAPPED 检查（上游同 bug） | `__esp_start` 早期清全部 CLIC 中断控制字节（`0x20801003 + i*4` 置 0，128 个） |
| 5. console | NuttX 启动到 idle 但无输出 | `esp_usbserial_write` 被调用（输出路径活）但数据未达主机（TX 端点/主机侧） | ⏳ **T2 第一项**；备选 UART0 console（CP2102 在线） |

## 坑 1：esptool rev3.2 stub 崩溃

- 现象：5.3.1/4.10 均 stub 崩溃（`Entering download mode` 后 OHAI 不达）；ROM 模式（--no-stub）USB 断流；UART0 下载模式无响应
- 根因：**ESP32-P4 rev3.2/ECO7 支持仅存在于 esptool ≥ v4.12.0**（2026-07-13 发布）
- 解决：`pip3 install --user "esptool==4.12.0"`；烧录用 `~/.local/bin/esptool.py --chip esp32p4 --port /dev/ttyACM0 write_flash <addr> <bin>`
- ⚠️ pip 升降级后 **重建 esptool 软链**（`ln -sf ~/.local/bin/esptool.py ~/.local/bin/esptool`）——mkimage 依赖

## 坑 2：JTAG 烧录（OpenOCD）的坑

- OpenOCD：`/tmp/openocd-esp32/openocd-esp32/bin/openocd`（v0.12.0-esp32-20260703，ghfast 下载）；配置 `-f board/esp32p4-builtin.cfg`（esp_usb_jtag 303a:1001 + esp32p4 target，flash 支持齐全）
- **`esp32p4_soc_reset` 会断 USB**（P4 系统复位含 USB-JTAG 控制器）→ 复位后设备重枚举（VMware 直通下加剧抖动）
- **ROM 复位后总是进下载模式等待**（strap 引脚配置）——`boot:0xf` 从 flash 启动需要特殊触发；**RAM 加载调试绕开 ROM 启动**：
  ```bash
  openocd -f board/esp32p4-builtin.cfg -c "init" -c "halt" \
    -c "load_image <nuttx ELF>" -c "resume <entry>" -c "shutdown"
  # 入口：riscv-none-elf-readelf -h nuttx | awk '/Entry point/ {print $4}'（$4！不是 $3）
  ```
- **`reg pc <val>` 无效**（SMP 双核）——用 `resume <entry>`（设 PC+运行一步）
- **OpenOCD `break` 命令传函数名会报 "expected integer"**；`bp` 命令在 esp32p4 上 "Invalid command argument"——**用 gdb**（`target remote :3333`，gdb 12.1 支持 riscv32）但 VMware 抖动下协议不稳
- 软件断点调试注意：`-c "wait_halt 10000"` 不命中会一直等

## 坑 3：烧录"成功"但没落盘（JTAG stub vs esptool）

- **JTAG stub flasher（flash write_image）报 wrote 但 ROM 读到的还是旧内容**——写入未真正落盘（XMC 缓存）
- **esptool 烧录可靠**（走 ROM 下载模式驱动，hash verified）——验证：`esptool.py read_flash <addr> 0x40 | xxd` 应看到 `e9 04`（ESP 镜像 magic）
- 判断依据：JTAG read_bank 读 0x0 = e9 04（JTAG stub 写的），ROM 启动却报 `invalid header: 0xc6b7c290`（旧内容）——**两次写入一次有效**

## 坑 4：LP WDT 复位循环（连 JTAG 都不稳）

- 现象：`Reset cause (16) - (LP WDT resets chip)` 反复；USB 设备号每次枚举都变；OpenOCD "Debug Module is not active"
- 根因：镜像卡死（中断风暴）→ `bootloader_config_wdt` 未执行 → LP WDT 超时复位 → 循环
- 解：修掉卡死根因（坑 1-4 的修复）；`bootloader_super_wdt_auto_feed` 配置后不再复位
- 调试经验：**串口监听要用自动重连脚本**（设备复位循环/重枚举时 cat 会挂）：
  ```bash
  for i in $(seq 1 30); do [ -e /dev/ttyACM0 ] && timeout 6 cat /dev/ttyACM0; sleep 1; done
  ```

## 坑 5：调试工具链细节

- **pkill/pgrep -f 自误杀**：命令行含匹配串就杀自己（exit 144）——模式用字符类 `"[o]penocd-esp32/bin"`，且 heredoc/路径里出现完整串也会被匹配
- **串口被占**：esptool 前 `fuser -k /dev/ttyACM0`（cat 监听占着端口会 Write timeout）
- **读内存验证 bss/中断表**：OpenOCD `mdw <addr> <n>`（halt 后）——bss 垃圾 = 中断表 g_irqvector 被污染（之前靠这个定位 XIP 污染）
- **CLIC 寄存器**：基址 0x20800000；每中断使能/优先级控制字节 `0x20801003 + i*4`（1 字节，0=禁用）；`CLIC_INT_INFO` 0x20800004（当前中断号）
- **P4 flash 数据映射区 0x8FF8xxxx**（XIP）——halt PC 落在这里 = MMU 被错误映射（XIP 污染症状）

## 坑 6：烧录/启动环境

- udev 规则（303a → 0666）：`/etc/udev/rules.d/99-esp.rules`（tty + usb 两条）
- **VMware USB 直通抖动**：设备号反复变——换 USB 线/口可缓解；设备号稳定窗口内操作
- esptool 连接超时 → 拔插 USB（ROM 干净回到下载模式）后重试

## 坑 7：构建环境（工作区改名后）

- 工作区改名后 cmake_out 全是旧路径：CMakeCache 缺失 → `cmake --build` 报 "could not load cache"；残留的 build.ninja 无法复用（路径全错）
- 全新配置步骤：`cmake -S nuttx -B cmake_out/<board>_<config> -G Ninja -DBOARD_CONFIG=boards/risc-v/esp32p4/esp32p4-function-ev-board/configs/nsh`
- 依赖：`pip3 install kconfiglib`；PATH 需含 `prebuilts/gcc/linux-x86_64/riscv-none-elf/bin`（ar/ranlib 用裸名）+ `prebuilts/build-tools/linux-x86_64/bin`（ninja）+ `~/.local/bin`（esptool）
- HAL 重拉：`export ESP_HAL_3RDPARTY_URL=https://ghfast.top/https://github.com/espressif/esp-hal-3rdparty.git`（ghfast 对 clone 有效，push 不行）
