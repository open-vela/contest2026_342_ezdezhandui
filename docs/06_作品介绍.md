## 一、一句话介绍

**桌伴（DeskMate）** 是一块基于 **openvela + ai_agent** 的 7 英寸智能视觉中控屏。
它装在书桌或玄关，**能看见、会主动、会执行**：摄像头看到你进门就主动问候，
早上到点自动播报天气与日程，说一句"记一下明早 9 点开会"就记下并到点提醒。

与"问答式"语音助手不同，桌伴的重点是**主动**：它不需要你先开口。

## 五、技术实现

### 5.1 移植路径（技术难度主攻）

在 NuttX 上游 `esp32p4` 全套支持的基础上，完成到 openvela `dev-ai-contest-2026`
的板级/芯片层移植。关键工程节点：

1. **串口 console 点亮** → **eth0 (RMII)** → **32MB PSRAM 可用**
2. **PSRAM 写 hang 根因定位**：bootloader PMP 时序缺陷（非硬件 bug），修复后 PSRAM 完全可用
3. **代码空间硬限制突破**（本项目最硬的一战）：
   - SIMPLE_BOOT 模式下代码只能跑在 512KB SRAM 窗口内，实测占用 463KB，仅余 49KB
   - 证据链证明窗口**不可扩容**：`SOC_DIRAM_ROM_RESERVE_HIGH=0x4ff40000`（低 256KB 为 ROM 保留区）
     + ROM 锁定 PMP + `CONFIG_SPIRAM_XIP_FROM_PSRAM` 为死代码
   - **解法**：切 **MCUboot 二级引导**，text+rodata（409KB）迁入 16MB flash 以 XIP 执行
     → **SRAM 占用 460KB → 83KB（释放约 430KB）**
   - 为此移植了 MCUboot 的 esp32p4 端口（上游无此板支持）：升级 MCUboot 到含 p4 的分支、
     修 ABI/工具链/头文件五类障碍（固化为幂等补丁 `mcuboot_p4_fixup.sh`），
     并自研两个工具让 NuttX 应用能被 MCUboot 加载（`mcuboot_mkloadhdr.py`、
     `mcuboot_p4_loader_patch.py`：映射 IROM + 使能 L1 cache 总线）
4. **空间释放后恢复被裁剪的 AI 能力**：`web_search`、`llm_vision`/`tool_vision`、`cron` 从弱桩变为真实实现

### 5.2 外设落地（本轮新增）

- **显示链路**：MIPI-DSI host（2 lane @ 900Mbps）→ EK79007 面板驱动（DPI 52MHz / 1024×600）
  → PSRAM 帧缓冲 → `/dev/fb0`；MIPI PHY 供电走片内 LDO 通道 3 @ 2.5V
- **触摸链路**：GT911（I2C0, SDA=GPIO7, SCL=GPIO8，轮询模式）→ `/dev/input0`
- **LVGL**：`GRAPHICS_LVGL` + `lv_nuttx` 胶水层，NSH 内置 `lvgldemo`
- **摄像头链路**：新增 NuttX MIPI-CSI 驱动（复用 HAL 内已有的 `esp_hal_cam`/`upper_hal_cam`
  CSI 控制器，仅补 NuttX 侧接线与一层 FreeRTOS 兼容头）+ SC2336 传感器驱动
  （SCCB @0x30、1080p30 RAW10 表）→ `/dev/video0`

### 5.3 主动场景的实现

- **定时主动**：`cron_add` 创建作业 → `cron_service` 线程按 10s 周期扫表 → 到点调用工具执行
  （如 `web_search` 取天气 → 生成播报 → 屏显/发消息）
- **事件主动**：CSI 采集帧 → `analyze_image`（LLM 视觉）→ 判定有人/异常 → 触发问候或告警，
  并把事件追加到 `ALERTS.md`

### 本轮发现并修复的平台级缺陷（影响面大于本功能）

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | 残留 0 字节 `boards/dummy/Kconfig` 使板级 Kconfig 永不生效 | **该板所有板级选项静默失效**（tab5 参考板同样中招） |
| 2 | `esp_lowputc_send_byte()` 不等 TX FIFO 空间即写 | 输出突发静默丢字节，实测吞掉 ai_agent 启动日志 ~1.5KB 与 CLI 提示符 |
| 3 | `gt9xx.c` 的 `ioctl = NULL` | `TSIOC_GETMAXPOINTS` 返回 -ENOTTY，LVGL 拒绝打开 `/dev/input0` |
| 4 | `v4l2_cap.c` 格式白名单拒绝裸 Bayer | 无 ISP 的 CSI 传感器无法出流 |

### 已知限制（诚实记录）

1. **屏与触摸模组未响应**：EK79007 面板 DCS 命令超时、GT911 在 I2C0 无应答。
   两者同属 LCD 模组，且 I2C0 本身可用（摄像头在 0x30 应答成功），
   故指向 **LCD 模组的连接/供电**（FPC 方向或 J1→J6 跳线），非驱动逻辑问题。
2. **摄像头采集尚未出帧**：模块识别与注册成功，但 V4L2 格式协商与上层缓冲区语义
   在 RAW10 下不匹配；彻底解法是接通 ISP 输出 RGB565/YUV422。
3. **ai_agent 串口交互（`vela>` CLI）输入不通**：输出侧已修复（提示符可见），
   输入侧 NSH 与 agent CLI 同时收不到字符，根因待继续定位。
4. **MiMo key 无效（HTTP 401）**：LLM 真实对话需有效额度。
