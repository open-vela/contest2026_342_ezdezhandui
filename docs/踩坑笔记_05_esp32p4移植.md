## 构建命令（完整可复现）

```bash
cd openvela
# 1. 切大赛分支（公开源手动切，等组委会 manifest 再 repo init 统一切）
for p in nuttx vendor_espressif packages_ai_agent; do
  (cd $p && git fetch https://gitee.com/open-vela/$p.git dev-ai-contest-2026:refs/remotes/m/contest && git checkout -f refs/remotes/m/contest)

# 2. 编译（HAL 自动 clone 到 cmake_out + 自动打 patch）
```

## 坑 1：HAL 版本锁定（ESP_HAL_3RDPARTY_VERSION）

- 上游锁定 commit 里旧版（0eb59f7e）**无 esp32p4 组件**（gpio_sig_map.h/irq.h/rom.eco5.ld 缺失）
- 换 NuttX master 最新锁定（8d0a898）→ 组件齐全
- ⚠️ **本地 nuttx-upstream fetch 后工作区还是旧 commit**（fetch 只更新 refs），cp 之前必须 `git checkout` 最新——本次曾因忘 checkout 白跑两轮

## 坑 2：debug.h 位置差异（openvela fork 特色）

- 上游用 `#include <nuttx/debug.h>`；**openvela 只有 `include/debug.h`**（nuttx/debug.h 不存在）
- 批量替换移植文件（arch 46 处 + boards 22 处）

## 坑 3：NUTTX_BINARY_DIR 未定义

- 上游 CMake 定义 `set(NUTTX_BINARY_DIR ...)`；openvela 没有 → HAL 路径解析成 `/arch/risc-v/...`（根路径）
- openvela nuttx/CMakeLists.txt 补定义

## 坑 4：链接脚本多文件（LD_SCRIPT 列表）

- esp32p4 的 ROM ld 文件（12+ 个）+ 板级脚本（aliases/flat_memory/sections）全部 APPEND 进 LD_SCRIPT **列表**
- openvela 的链接处理只支持单文件（get_filename_component 报 unknown component）→ 改 foreach（对齐上游）：每个 ld 预处理 + `-T file` 列表
- ⚠️ `esp32p4_sections.rev3.ld` 的 "contains output sections" warning 无害（ld 自动识别脚本），不阻断

## 坑 5：riscv_mtimer 条件编译

- openvela 无条件编译 riscv_mtimer.c（用 start_absolute 新接口）；CONFIG_ONESHOT 未开时 oneshot_operations_s 无该成员 → 编译错
- 对齐上游：`if(CONFIG_ONESHOT)` 条件编译（同时修复 openvela 其他 RISC-V 板的潜在问题）

## 坑 6：HAL 适配层与 openvela API 差异（patch 机制固化）

HAL（为上游 NuttX API 写的）在 openvela 上编译差异，**必须 patch 并固化**（HAL 在 cmake_out，rm 后重 clone 会丢手工修改——本次丢过一次！）：

| API | HAL 用法 | openvela | 处理 |
|---|---|---|---|
| `nxtask_init` | 9 参（旧签名） | 7 参（tcb,name,entry,actions,attr,argv,envp） | patch os.c：posix_spawnattr 模式（照 nxthread_create） |
| `fcntl.h` | 未 include（上游间接有） | 需显式 | patch os.c 加 include |
| `nxsched_usleep` | 直接用 | 无此 API（用 nxsig_usleep） | patch os.h 内联函数 |

固化方式：`nuttx/arch/risc-v/src/esp32p4/patches/0001-openvela-compat-os.c.patch`（git diff 生成）+ `common/espressif/CMakeLists.txt` 在 HAL populate 后 `execute_process git apply`（参照上游 mbedtls patch 机制，先 --check 再 apply）。

## 坑 7：工具链无 libatomic

- riscv-none-elf（openvela prebuilts）**没有 libatomic.a**（find 无结果）
- RV32IMC 无 64 位原子指令 → `__atomic_fetch_or_8`（esp_gpio_reserve 用）需自实现
- 解法：`esp32p4_atomic.c`（up_irq_save/restore 保护，单核足够；SMP 开时需升级 spinlock）
- ⚠️ `-latomic` 链接参数对静态库无效（PRIVATE 不传播；INTERFACE 可以但工具链没库——最终删掉用自实现）

## 坑 8：openvela 缺 espressif 工具脚本

- `tools/espressif/` 缺 6 个文件（espressif_mkimage.cmake、espressif_esptool_common.cmake、espressif_flash.cmake、espressif_burn_enc_key.cmake、burn_flash_enc_key.py、chip_info.py）→ 从上游补
- mkimage 报 "Error processing file" 就是文件缺失（不是语法错）

## 坑 9：board_app_initialize 缺失

- openvela BOARDCTL=y 时 boardctl.c 调 board_app_initialize——esp32p4 板级没有（上游无 appinit 文件）
- 新建 esp32p4_appinit.c（照 esp32c6 模式，CONFIG_BOARD_LATE_INITIALIZE 分支）+ board src/CMakeLists.txt 注册（CONFIG_BOARDCTL 下）
