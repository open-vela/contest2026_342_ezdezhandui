# 02_驱动实现 —— 板载音频与 WiFi 的「做到哪、没做到哪」

> 想知道这两项**交付边界**的人必读：ES8311 音频「驱动链路已编入固件、构建 0 error，板端出声待上板复测」；
> WiFi「主机侧驱动完整实现并逐条仪器验证，从机数据通路不工作，**WiFi 未交付**」，联网仍靠 eth0。
> 本目录说明与索引编制于 2026-10-31（各文件最后更新以文件内标注为准）。

## 本目录做什么

放**两条驱动的实现、验证与交付结论**：音频（ES8311 + I2S/GDMA）、WiFi（板载协处理器 + SDIO/ESP-Hosted），
以及「少改上游树」约束下的改动审计。**不放**项目流程与状态总览（`docs/01_开发流程/STATUS.md`）、
不放单点故障的历史排查（那在 `docs/03_踩坑笔记/`）。**引用交付结论前先读 [WiFi交付说明.md](WiFi交付说明.md)**。

1. [WiFi交付说明.md](WiFi交付说明.md) —— 先拿结论与边界；

## 维护约定

- 新增文档若讲**某条驱动/某个外设怎么实现**，归本目录；讲流程归 `docs/01_开发流程/`，讲单个坑归 `docs/03_踩坑笔记/`。
- 交付类文档必须**先写结论与边界**（做到了什么 / 没做到什么 / 为什么），排查过程另开一篇，不要把结论埋在过程里。
- 文件名语义化，**不带旧编号**（旧 `docs/07_ES8311…`、`docs/08`、`docs/09`、`docs/10` 的对照见 `docs/README.md`）。
- 跨目录引用一律写全路径，如 `docs/01_开发流程/STATUS.md`；本目录新增文件时同步更新本文件表格。
