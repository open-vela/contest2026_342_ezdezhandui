## 三、模块设计

### 3.1 启动链路（MCUboot 二级引导 + flash XIP，已完成）

```
ROM（flash 0x2000 读 MCUboot 引导）
  → MCUboot（24,672 B @ 0x2000）
      · 读 load header（magic 0xace637d3，自研 mcuboot_mkloadhdr.py 生成）
      · memcpy SRAM 段（IRAM/DRAM）到 RAM
      · MMU 映射 IROM 区 + 使能 L1 cache 总线（自研 mcuboot_p4_loader_patch.py 补）
  → 跳转应用入口（flash XIP 执行 text+rodata）
  → __esp_start（MCUboot 模式跳过 esp_clk_init —— 否则改 PLL 时 flash 取指停顿导致 WDT 复位）
  → nx_start → nsh / ai_agent
```

**为何必须切二级引导**：SIMPLE_BOOT 下代码只能在 512KB SRAM 窗口内执行，实测占用 463KB，
仅余 49KB；且该窗口**不可扩容**（低 256KB 是 ROM 保留区 + ROM 锁定 PMP）。
切 MCUboot 后 text+rodata（409KB）迁入 16MB flash 以 XIP 执行：
**SRAM 静态占用 460KB → 120.3KB**，这是 LVGL / 摄像头 / 语音等大功能的解锁前提。

### 3.2 这个数字怎么量（可复现）

判据是链接脚本里的 `sram_seg`（`0x4ff40000`，长度 `0x80000` = 512 KB）用量：

```bash
# 干净树构建后，直接数 map 中落在 sram_seg 地址区间的输出段
python3 - <<'EOF'
import re
tot={}
for line in open('cmake_out/esp32p4-function-ev-board_nsh/nuttx.map'):
    m=re.match(r'^([.\w]+)\s+0x([0-9a-f]{8,16})\s+0x([0-9a-f]+)\s*$', line.rstrip())
    if m and 0x4ff40000 <= int(m.group(2),16) < 0x4ffc0000:
        tot[m.group(1)] = tot.get(m.group(1),0) + int(m.group(3),16)
print(sum(tot.values()), tot)
EOF
```

2026-09-17 实测：`.dram0.bss` 79,624 B + `.iram0.text` 32,778 B + `.dram0.data` 10,788 B
= **123,190 B ≈ 120.3 KB / 512 KB（23.5%）**。

> 早期文档里的 **83 KB** 是 2026-09-11 刚切二级引导时的数值（当时 bss ≈ 53KB）；
> 之后陆续编入 LVGL / GT911 / MIPI-DSI / 摄像头 / WebSocket，SRAM 用量随之上升。
> 迁移前 text+rodata 都在 SRAM（约 460KB）会触发 `region 'sram_seg' overflowed`，
> 这一因果关系不变。

关键修复（SIMPLE_BOOT 时代 4 处 + MCUboot 时代 6 处）：
1. `flat_memory.ld`：SIMPLE_BOOT 条件 + rev3 `sram_seg`
2. 烧录偏移 0x2000（P4 BL_OFFSET）+ esptool ≥4.12
3. `esp_start.c`：SIMPLE_BOOT 跳过 `map_rom_segments`
4. `esp_start.c`：早期禁用全部 CLIC 中断（风暴）
5. MCUboot 无 p4 端口 → 升级到含 p4 的 master 分支（五类障碍固化为 `mcuboot_p4_fixup.sh`）
6. 链接脚本：MCUboot 模式下显式定义 `_image_irom_lma/_image_drom_lma` 为槽内 flash 偏移
7. MCUboot 模式跳过 `esp_clk_init()`（见上）
8. **`CMakeLists.txt`**：残留 0 字节 `boards/dummy/Kconfig` 会使板级 Kconfig 永不生效
   （本板所有板级选项静默失效；tab5 参考板同样中招）
9. **`esp_lowputc.c`**：`send_byte` 不等 TX FIFO 空间即写 → 输出突发静默丢字节
10. **`gt9xx.c`**：`ioctl = NULL` → LVGL 无法打开 `/dev/input0`

**flash 布局（16MB 物理 / MCUboot 视野前 4MB）**：
```
0x000000-0x002000  ROM 引导        0x020000-0x1E0000  OTA_0 主槽(1.75MB) ← 应用
0x002000-0x020000  MCUboot 引导    0x1E0000-0x3A0000  OTA_1 副槽
0x3A0000-0x3E0000  scratch         ── 4MB 以上归应用 ──
```

### 3.2 Console（UART0 → CP2102）

- console 走 **UART0**（`CONFIG_UART0_SERIAL_CONSOLE=y`，`CONFIG_ESPRESSIF_USBSERIAL` 已关闭）
- 物理端口：**`/dev/ttyUSB0`**（CP2102 UART 桥）；`/dev/ttyACM0`（USB-Serial/JTAG）仅用于烧录与 ROM/MCUboot 日志
- ⚠️ **打开串口必须 assert DTR/RTS**，否则读到的永远是 0 字节（`tools/test/board.py` 已内置）
- `CONFIG_UART0_TXBUFSIZE=2048`（默认 256 会让启动突发丢字节）

### 3.3 网络（EMAC / eth0）

- 驱动：`esp_emac.c`（esp_eth 栈——MAC+PHY+SMI）
- 引脚（官方默认 V1.5.2）：MDC=GPIO31 / MDIO=GPIO52 / RMII_CLK=GPIO50 / PHY_ADDR=1
- 依赖：NET + IOB_NCHAINS + riscv_netinitialize（已补）
- **当前卡点**：esp_eth_mac_new_esp32 初始化失败（需 console 日志）

### 3.4 ai_agent（MiMo）

- 包：`packages/ai_agent`（openvela 官方——goldfish 已验证）
- 配置参考：`defconfigs/esp32s3-eye/`（同类芯片预设）
- 依赖：网络 + mbedTLS（HTTPS）+ CJSON + DNS
- **当前卡点**：mbedTLS 配置链（MD_C 等 Kconfig 缺失）

## 四、关键机制

| 机制 | 说明 |
|---|---|
| SIMPLE_BOOT（ram-only）| 镜像仅 RAM 段（0x4FF40000），ROM 从 flash 0x2000 加载 |
| 中断体系（CLIC）| 硬件向量中断（mtvt），每中断 intctl 优先级 |
| 文件树移植 | 公版 + 适配分层（git 4 提交结构：公版/xml/适配/文档）|
| export / manifest | 工作区 → 文件树 → `<copyfile>`（repo sync 自动落位，**无需 deploy**）|
| 日志归集 | contest-log-collector（会话日志 → logs/）|
| JTAG 调试 | OpenOCD halt/load_image/resume + 内存读取（console 未通时验证手段）|
