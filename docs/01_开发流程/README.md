# 01_开发流程 —— 按时间与流程串起项目主线的 8 篇文档

> 评审/接手者从这里建立「项目是怎么一步步做出来的」的整体印象；
> **想知道当前是什么状态，只读 [STATUS.md](STATUS.md)**，其余文档都带时间戳。
> 本目录说明与索引编制于 2026-10-31（各文件最后更新以文件内标注为准）。

## 本目录做什么

放**项目主线**：规划与方案、需求与风险、工程框架与日常开发、模块设计、功能闭环测试、开发过程复盘、当前状态。
**不放**单个驱动的实现细节（`docs/02_驱动实现/`）、单点故障排查（`docs/03_踩坑笔记/`）、原始证据文件（`docs/04_证据/`）。
本目录下多篇文档内含**历史快照段落**，README 只负责指路，结论口径以 STATUS.md 为准。

## 维护约定

- 新增文档若描述**流程、规划、状态、测试**，归本目录；只讲某个驱动怎么实现归 `docs/02_驱动实现/`。
- 文件名语义化，**不带旧编号**（目录重整前的旧编号下，本目录曾是 `docs/01`–`docs/06` 与 `docs/STATUS.md`；对照见 `docs/README.md`）。
- 状态类结论只写在 [STATUS.md](STATUS.md) 一处，其他文档引用它，不各自维护一份。
- 跨目录引用一律写全路径，如 `docs/03_踩坑笔记/04_MCUboot与FlashXIP.md`；本目录新增文件时同步更新本文件表格。
