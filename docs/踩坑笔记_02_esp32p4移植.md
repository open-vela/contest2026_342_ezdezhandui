## 构建命令（完整可复现）

```bash
cd openvela
# 切大赛分支
for p in nuttx vendor_espressif packages_ai_agent; do
  (cd $p && git fetch https://gitee.com/open-vela/$p.git dev-ai-contest-2026:refs/remotes/m/contest && git checkout -f refs/remotes/m/contest)
done

# 编译（HAL 自动 clone 到 cmake_out + 自动打 patch）
./build.sh nuttx/boards/risc-v/esp32p4/esp32p4-function-ev-board/configs/nsh/ --cmake -j8
# 产物：cmake_out/esp32p4-function-ev-board_nsh/nuttx.bin
```

## 坑 1：HAL 版本锁定（ESP_HAL_3RDPARTY_VERSION）

- 旧锁定 commit（0eb59f7e）**无 esp32p4 组件**（gpio_sig_map.h/irq.h/rom.eco5.ld 缺失）；换 8d0a898 → 组件齐全
- ⚠️ fetch 后必须 `git checkout`（fetch 只更新 refs，工作区还是旧 commit——曾白跑两轮）
- ⚠️ HAL 在 cmake_out（FetchContent clone）——**rm cmake_out 会重拉**（走 ghfast 代理 URL：`export ESP_HAL_3RDPARTY_URL=https://ghfast.top/https://github.com/espressif/esp-hal-3rdparty.git`）

## 坑 2：debug.h 位置差异（openvela fork 特色）

- 上游 `#include <nuttx/debug.h>`；**openvela 只有 `include/debug.h`** → 批量替换（arch 46 处 + boards 22 处）

## 坑 3：NUTTX_BINARY_DIR 未定义

- 上游 CMake 定义；openvela 没有 → HAL 路径解析成根路径 → nuttx/CMakeLists.txt 补定义

## 坑 4：链接脚本多文件（LD_SCRIPT 列表）

- esp32p4 的 ROM ld 文件（12+ 个）+ 板级脚本全部 APPEND 进 LD_SCRIPT **列表**；openvela 只支持单文件 → 改 foreach（对齐上游）：每个 ld 预处理 + `-T file` 列表
- ⚠️ `esp32p4_sections.rev3.ld` 的 "contains output sections" warning 无害

## 坑 5：riscv_mtimer 条件编译

- openvela 无条件编译 riscv_mtimer.c；CONFIG_ONESHOT 未开时 oneshot_operations_s 无成员 → 对齐上游 `if(CONFIG_ONESHOT)` 条件编译（影响所有 RISC-V 板，需回归 goldfish）

## 坑 6：HAL 适配层与 openvela API 差异（patch 机制固化）

HAL（为上游 NuttX API 写的）在 openvela 上编译差异，**必须 patch 并固化**（HAL 在 cmake_out，rm 后重 clone 会丢手工修改——丢过一次！）：

| API | HAL 用法 | openvela | 处理 |
|---|---|---|---|
| `nxtask_init` | 9 参（旧签名） | 7 参 | patch os.c（照 nxthread_create） |
| `fcntl.h` | 未 include | 需显式 | patch os.c 加 include |
| `nxsched_usleep` | 直接用 | 无（用 nxsig_usleep） | patch os.h 内联 |

固化：`nuttx/arch/risc-v/src/esp32p4/patches/0001-openvela-compat-os.c.patch`（git diff 生成）+ `common/espressif/CMakeLists.txt` 在 HAL populate 后 `git apply`（先 --check 再 apply，参照上游 mbedtls patch 机制）

## 坑 7：工具链无 libatomic

- riscv-none-elf 没有 libatomic.a；RV32IMC 无 64 位原子指令 → `__atomic_fetch_or_8` 需自实现
- 解法：`esp32p4_atomic.c`（up_irq_save/restore 保护，单核够用；SMP 需 spinlock）
- ⚠️ `-latomic` 对静态库无效（PRIVATE 不传播）——最终删掉用自实现

## 坑 8：openvela 缺 espressif 工具脚本

- `tools/espressif/` 缺 6 个文件（mkimage/esptool_common/flash/burn_enc_key/chip_info）→ 从上游补
- mkimage 报 "Error processing file" = 文件缺失（不是语法错）

## 坑 9：board_app_initialize 缺失

- openvela BOARDCTL=y 时 boardctl.c 调 board_app_initialize——esp32p4 板级没有 → 新建 esp32p4_appinit.c（照 esp32c6 模式）+ CMakeLists 注册

## 坑 10：esptool 软链必须

- `ln -sf ~/.local/bin/esptool.py ~/.local/bin/esptool`——CMake find_program 多 NAMES 找不到 esptool.py，mkimage 会失败
- ⚠️ **pip 升级/降级 esptool 会删掉这个软链**（本次 pip 装 4.12 后软链消失 → mkimage 失败）——升级后必须重建
