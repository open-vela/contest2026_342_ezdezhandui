> 2026-08-06/12 于 Ubuntu 22.04 / 中国网络环境。目标：`goldfish-armv8a-ap>` 提示符 + `ai_agent`（ask 命令）跑通。
> **结论：均已跑通**——repo sync（gitee 源）→ 构建 → 模拟器 NSH → `ask 现在几点了` 正确应答（ReAct 工具链路工作）。

## 一次成功的最小路径（直接照抄）

```bash
# 1. 环境（repo 2.65 + python3 软链）
curl -sSL https://storage.googleapis.com/git-repo-downloads/repo -o ~/.local/bin/repo && chmod +x
ln -sf /usr/bin/python3 ~/.local/bin/python   # python2 抢 CMake 的 Python3（见坑 4）

# 2. 同步（gitee 源 + ghfast 代理）
repo init -u https://gitee.com/open-vela/contest2026_342_ezdezhandui.git -b dev-ai-contest-2026 \
  --repo-url=https://ghfast.top/https://github.com/GerritCodeReview/git-repo.git
repo sync -c -j8

# 3. 启用 AI Agent + 构建
echo "CONFIG_EXAMPLES_AI_AGENT_VELA=y" >> vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap/defconfig
./build.sh vendor/openvela/boards/vela/configs/goldfish-arm64-v8a-ap/ --cmake -j8

# 4. 运行（关键：管道喂 stdin + -qemu -nographic，见坑 2/3）
(sleep 40; printf "ask 现在几点了\n"; sleep 15; printf "quit\n") \
  | ./emulator.sh vela -no-window -no-audio -gpu off -qemu -nographic > /tmp/emu.log 2>&1

# 5. 模拟器镜像软链（缺了会 "No initial vela_system image"，见坑 6）
cd openvela
ln -sf ../cmake_out/vela_goldfish-arm64-v8a-ap/nuttx         nuttx/nuttx
ln -sf ../cmake_out/vela_goldfish-arm64-v8a-ap/vela_system.bin nuttx/vela_system.bin
ln -sf ../cmake_out/vela_goldfish-arm64-v8a-ap/vela_data.bin   nuttx/vela_data.bin
```

## 坑 1：系统 repo 2.17 不支持 `--git-lfs`

- 现象：`repo init ... --git-lfs` → `error: no such option`
- 解决：下载新版 launcher 到 `~/.local/bin/repo`（GCS 直连可用）；⚠️ `~/.local/bin` 不在默认 PATH，用全路径

## 坑 2：repo init 卡死（gerrit 自举被墙）

- 现象：`repo init` 无输出挂死，`.repo/repo.tmp` 只有 116K
- 根因：默认从 `gerrit.googlesource.com` 自举，国内不可达；tuna 镜像实测也挂死（12 分钟 116K）
- 解决：`--repo-url=https://ghfast.top/https://github.com/GerritCodeReview/git-repo.git`（⚠️ 不是 android/git-repo，该仓库已不存在）

## 坑 3：repo sync 部分仓库损坏

- 现象：`fatal: 不是 git 仓库：'.repo/projects/vendor/xiaomi/vela.git'`
- 解决：`rm -rf .repo/projects/<坏仓> <坏仓工作目录>` 后重跑 sync（断点续传，48GB 不用重下）
- ⚠️ repo sync 遇 TLS 中断：重试即可（幂等）；gitee 源全量约 40 分钟

## 坑 4：python2 抢 CMake 的 Python3

- 现象：`Could NOT find Python3 ... Wrong major version for "/usr/local/bin/python"`（/usr/local/bin/python → python2.7）
- 两种解法：构建时 `PATH=/usr/bin:$PATH ./build.sh ...`；或 `ln -sf /usr/bin/python3 ~/.local/bin/python`（~/.local/bin 在 PATH 最前）

## 坑 5：build 缓存残留

- 现象：`could not find CMAKE_PROJECT_NAME in Cache`
- 解决：`rm -rf cmake_out` 后重新构建（失败过的 configure 留下坏缓存）
- ⚠️ 工作区改名/移动后：CMakeCache 缺失 → `cmake --build` 报 "could not load cache"，需重新配置（见笔记 #03 坑 10）

## 坑 6：模拟器 `No initial vela_system image`

- 解决：构建产物软链到源码树 `nuttx/`（run_emulator.sh 从 `$TOP_DIR/nuttx/` 找镜像）——注意相对路径 `../cmake_out/...`

## 坑 7：无显示器环境跑模拟器

- 用 `-no-window -no-audio -gpu off -qemu -nographic`，串口输出到 stdout；启动 40-60s（arm64 TCG）

## 坑 8：expect/pty 无法输入 guest console，管道可以

- **现象**：expect spawn 模拟器（pty），send 命令无回显无响应
- **根因**：Android emulator 从 stdin 读自己的 console 命令，非 tty stdin（管道）时才透传给 guest
- **正解**：`printf "...\n" | ./emulator.sh vela ...`（管道喂 stdin）
- 补充：`-nographic` 必须加（不加只有输出、stdin 不达 guest）；adb shell / telnet 2323 / console 5554 均不可用——**stdin 管道 + -nographic 是唯一可靠交互通道**

## 坑 9：pkill/ps 自误杀（三次！）

- `pkill -f "emulator.*vela"`、命令行里含匹配模式的任何 pgrep/kill 都会杀掉当前 shell 自己（exit 144）
- 正解：grep 用 `[q]emu` 字符类；**pgrep/pkill -f 时模式里也必须用字符类**（`"openocd-esp32/[b]in"`），且**避免命令行里出现完整匹配串**（如 heredoc 内容含路径也会被匹配）

## 坑 10：AVD 冲突 + cwd 漂移

- 旧模拟器没死透就启动新的 → `Running multiple emulators with the same AVD`；换配置前先杀干净（`ps -eo pid,cmd | grep -iE "[q]emu"`）
- Bash 会话 cwd 会重置；build.sh/emulator.sh 依赖 openvela 根 cwd → 用绝对路径或 `cd <workspace> &&`
