# 桌伴 DeskMate 需求与风险分析

> 2026-08-24 更新 · openvela AI 硬件开发者大赛（小米）· 队伍 342

## 一、项目定位与需求

### 1.1 产品定位

**桌伴 DeskMate** —— 7 英寸"能看见、会主动、会执行"的 AI 视觉中控屏。
基于 openvela（NuttX）+ **ESP32-P4X-C5-Function-EV-Board**（官方待适配板）：
摄像头事件主动（MIPI-CSI 2MP）+ 语音（ES8311 codec）+ LVGL 7" 屏 +
ai_agent（MiMo 大模型）+ 以太网保底联网。

### 1.2 赛题需求映射

| 赛题四点 | 实现方案 | 状态 |
|---|---|---|
| ① Agent 硬件跑起来 | ESP32-P4X 移植 openvela（公版驱动 + BSP 适配）| ✅ NuttX 内核完整启动（调度器 idle）|
| ② ≥1 自定义 Skill | 摄像头事件主动 Skill（"发现人靠近 → 主动问候"）| 🔶 设计完成，待外设就绪 |
| ③ ≥1 主动+执行场景 | 主动播报（时间/天气/待办）+ 语音指令执行 | 🔶 依赖 ai_agent + 语音 |
| ④ 应用场景说明 | 桌面智能助手：日程提醒/环境感知/语音交互 | 📝 规划文档 V5.1 |

## 二、风险分析

### 2.1 技术风险

| # | 风险 | 概率 | 影响 | 状态/缓解 |
|---|---|---|---|---|
| R1 | **P4 rev3.2 工具链兼容**（esptool stub 崩溃）| 已发生 | 高（烧录）| ✅ 解决：esptool ≥4.12（rev3.2/ECO7 支持）|
| R2 | **SIMPLE_BOOT 启动链路**（链接布局/XIP/中断）| 已发生 | 高（无法启动）| ✅ 解决：4 处根因修复，NuttX 完整启动 |
| R3 | **CLIC 中断使能机制**（console 输出卡缓冲）| 进行中 | 高（无交互通道）| 🔶 调查到最后一环：P4 使能位图寄存器未明，需对照 ESP-IDF |
| R4 | **EMAC 初始化失败** | 进行中 | 中（无网络）| 🔶 esp_eth_mac_new_esp32 失败，需 console 日志定位 |
| R5 | **mbedTLS 配置链**（MD_C 等 Kconfig 缺失）| 进行中 | 中（ai_agent 阻塞）| 🔶 openvela mbedtls 体系研究；goldfish 兜底可用 |
| R6 | **VMware USB 直通抖动** | 已发生 | 中（调试效率）| ✅ 换线缓解；设备号稳定窗口内操作 |
| R7 | **烧录偏移/落盘**（P4 bootloader=0x2000）| 已发生 | 高（镜像无效）| ✅ 解决：官方 BL_OFFSET + esptool 落盘验证 |
