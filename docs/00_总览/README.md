# 00_总览 —— 讲清「上游 openvela 是怎么搭起来的」的平台全景

> 适合刚接手本工程、需要先建立平台级全局认知的人（含评审）。
> 本篇只讲**上游 openvela 整体**，本项目自己的模块划分见 `docs/01_开发流程/框架模块设计.md`。
> 本目录说明与索引编制于 2026-10-31（正文文件的最后更新以文件内标注为准，现为 2026-09-16）。

## 本目录做什么

放**平台级背景**：repo/manifest 多仓工程形态、分层架构、Kconfig、构建系统、启动链、术语表与自查命令。
**不放**本项目设计（那在 `docs/01_开发流程/框架模块设计.md`）、不放踩坑过程（那在 `docs/03_踩坑笔记/`）、
不放状态结论（那在 `docs/01_开发流程/STATUS.md`）。本目录是「读代码前的地图」，不承担结论口径。

## 文件说明

| 文件 | 内容 | 什么时候读它 |
|---|---|---|
| [openvela系统框架解读.md](openvela系统框架解读.md) | 上游 openvela 的工程组织与整体架构（面向本项目） | 第一次读本仓代码前；想知道某个路径/配置从哪来、想复制自查命令核实时 |

## 阅读顺序

1. [openvela系统框架解读.md](openvela系统框架解读.md) §〇/§一 —— 先弄清「openvela ≈ NuttX + frameworks + packages + vendor/boards + repo/manifest + 统一构建」；
2. 再读 `docs/01_开发流程/工程框架与日常开发.md` —— 看本项目的工作区、四个源仓与作品仓的分工；
3. 之后才读 `docs/01_开发流程/框架模块设计.md` 与具体驱动文档，否则容易把上游能力误当成本项目成果。

## 维护约定

- 新增文档若讲的是**上游/平台本身**（不是本项目做了什么），归本目录；讲本项目流程、实现、踩坑、证据的分别归 `docs/01_开发流程/`、`docs/02_驱动实现/`、`docs/03_踩坑笔记/`、`docs/04_证据/`。
- 文件名语义化，**不带旧编号**（旧 `docs/00_openvela系统框架解读.md` 的对照见 `docs/README.md`）。
- 跨目录引用一律写全路径，如 `docs/01_开发流程/STATUS.md`。
- 本目录新增文件时，同步更新本文件的表格。
